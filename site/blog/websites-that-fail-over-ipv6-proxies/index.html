Why Some Websites Won't Open Through an IPv6 Proxy (and Fixes That Don't Leak IPv4)

November 11, 2026 · 5 min read

In short

A site fails through an IPv6 proxy for one of three reasons: your DNS hides its IPv6 record, the site has no IPv6 at all, or the site refuses connections from your IPv6 range. Fix the first with encrypted DNS lookups, the second with a NAT64 gateway on a VPS (not your home IPv4), and the third with a proxy on another network. openv6's “Test a website” tells you which one it is.

You set up IPv6 proxies, most sites work, and then one site simply won't load: a timeout, a 502, or the anti-detect browser saying the connection failed. The same site opens fine in your normal browser. What's going on?

Your normal browser has both IPv4 and IPv6 and quietly uses whichever works. A pure IPv6 proxy has only IPv6. So when a site fails, it is almost always one of three things, and each has a different fix. Some "fixes" you will find online expose your real IPv4, which defeats the point of using separate proxies at all. This guide sticks to fixes that don't.

The three causes

CauseWhat happensHow common
DNS hides the IPv6 recordThe site has IPv6, but your router, ISP or VPN DNS does not return its AAAA record, so the proxy thinks there is no IPv6.Common on some home routers and VPN DNS
The site is IPv4-onlyThe site has no IPv6 address at all. No IPv6 proxy can reach it directly.Common: many smaller sites, some APIs, some proxy-check services
The site refuses your IPv6The site has IPv6 but blocks your range, or the IPv6 path to it is broken.Rare, mostly anti-bot systems and some hosting providers

Find out which one it is

You can check by hand. Ask a public resolver directly whether the site has IPv6:

nslookup -type=AAAA example.com 1.1.1.1

Then ask your normal DNS the same question (drop the 1.1.1.1). If the public resolver returns an IPv6 address and your own DNS doesn't, it is cause 1. If neither returns one, it is cause 2. If both return an address but this still fails:

curl -6 -I https://example.com

then the site is refusing your IPv6 or the path is broken: cause 3.

In openv6 you don't have to do this by hand. Open a proxy, go to Test a website, type the domain, and click Test. The proxy machine runs the checks above, from the proxy's own IPv6, and shows the verdict with the addresses it found and the fix.

Fix 1: DNS hides IPv6, use encrypted DNS

When the router or VPN DNS strips AAAA records, the site is reachable over IPv6; the proxy just can't find the address. The fix is to look the name up somewhere that tells the truth.

openv6 does this automatically with Encrypted DNS fallback (Settings → Website access, on by default). When normal DNS returns no IPv6, the proxy asks Cloudflare or Google over DNS-over-HTTPS, connecting to them over the proxy's own IPv6. Nothing goes over IPv4, and the ISP does not see the query. The site then opens over IPv6 like any other.

If you run your own proxy software instead, point its resolver at a public DNS server that returns AAAA records, and make sure that lookup goes over IPv6 too.

Fix 2: IPv4-only sites, use NAT64, not your home IPv4

An IPv4-only site needs an IPv4 address on the other end. You have three choices, and they differ a lot in what the site sees:

Choice (openv6 setting)What the site seesVerdict
Never use IPv4 (default)Nothing. The site does not open.Safest. Fine if you don't need those sites.
Through a NAT64 gatewayThe IPv4 of your NAT64 gateway, usually a cheap VPS.Recommended when you need IPv4. Your home IP stays hidden.
This machine's IPv4The real IPv4 of the proxy machine: your home IP, shared by every proxy that uses it.Avoid for account work. It links every account to one IP.

The last option is what most "IPv4 fallback" switches do, and it is the leak to watch for. Every profile that reaches an IPv4-only site through it shows up from the same address: your real one. Anti-fraud systems link accounts on exactly that.

NAT64 avoids it. A NAT64 gateway takes connections to a special IPv6 prefix (a /96, such as 64:ff9b::/96) and forwards them to the IPv4 address embedded in it. Run one on a VPS (Jool is the usual choice on Linux), enter its prefix in openv6, and IPv4-only sites go out over IPv6 to the VPS, which connects to them over its own IPv4. The site sees the VPS. The proxy machine never uses its own IPv4. If the gateway is down or the prefix is wrong, those sites fail to open; they never fall back to your home IP.

Two things to keep in mind:

  • Every proxy that reaches IPv4-only sites through the gateway shares the gateway's IPv4. That is fine for things like a proxy-check service or a CDN, but don't log in to accounts on IPv4-only sites from many profiles through one gateway.
  • You don't have to send every IPv4-only site through it. openv6's Sites allowed over IPv4 list lets you name just the ones you need (for example the IP-check service of your anti-detect browser), while IPv4 fallback stays off on the proxies themselves.

The setup steps are in docs/NAT64.md in the openv6 repository.

Fix 3: The site refuses your IPv6

If the site has IPv6 and a direct curl -6 fails or returns 403, the site (or its CDN) doesn't like your range, or the route to it is broken. Your options:

  • Get a new address inside your prefix (openv6: New IPv6). If the site blocks a single address, this helps; if it blocks the whole /64, it won't.
  • Use a proxy on another network: another ISP at home, or a VPS with its own IPv6 range.
  • Check the network. A VPN or firewall with an IPv6 kill switch on the proxy machine can break IPv6 to some destinations only.

Bonus: the site is blocked on purpose

If you added the site to openv6's Blocked sites list, the proxy refuses it with a 403 (HTTP) or "not allowed" (SOCKS5). "Test a website" says so explicitly, so you don't waste time looking for a network problem.

Summary

  1. Test the site from the proxy and find out which of the three causes it is.
  2. Hidden IPv6 record: turn on encrypted DNS lookups.
  3. IPv4-only site: send it through a NAT64 gateway on a VPS, and only the sites you need. Don't use the machine's own IPv4.
  4. Refused IPv6: new address, or a proxy on another network.

Frequently asked questions

Why does a site open in my normal browser but not through the IPv6 proxy?

Your normal browser falls back to IPv4 silently. An IPv6 proxy has no IPv4 to fall back to unless you give it one, so an IPv4-only site, or a site whose IPv6 record your DNS hides, fails.

Is turning on IPv4 fallback safe?

Not for account work. Fallback sends IPv4-only sites out through the proxy machine's real IPv4, which every proxy with fallback shares. The sites then see your home IP and can link the accounts.

What is NAT64 and why is it safer?

A NAT64 gateway turns an IPv6 connection into an IPv4 one. Run it on a cheap VPS and IPv4-only sites see the VPS's IPv4, never your home IP, while the proxy itself still only speaks IPv6.

Does encrypted DNS leak anything?

openv6 sends DNS-over-HTTPS queries to Cloudflare or Google from the proxy's own IPv6. No IPv4 is used, and your ISP cannot see which names are looked up.
