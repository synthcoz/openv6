A VPS is the easiest place to run IPv6 proxies that never change. The address space comes with the server, the uptime is better than a home connection, and with the right prefix you can give every proxy a completely separate network.

Why a VPS?

  • Fixed prefix. Unlike most home ISPs, a VPS prefix does not change.
  • Public IPv4. Clients connect to VPS-IP:port from anywhere, no relays or port forwarding.
  • Bigger prefixes. Some providers route a /56 or /48 to your server, which means thousands to 65,536 separate /64 networks.

The trade-off: VPS addresses are datacenter addresses. For residential IPs, use your home connection; many people run both.

On-link /64 vs routed /56 or /48

This is the one technical detail worth understanding before you start.

On-link /64Routed /56 or /48
What you getOne /64 on the server's network cardA whole prefix routed to your server
How proxies get addressesEach address is added to the cardThe server answers for every address in the range
openv6 pool modeauto (detected automatically)anyip (you add the CIDR)
Separation between proxiesAll in one /64One /64 per proxy possible
How commonAlmost every providerSome providers, sometimes on request

If you are not sure which one you have, start with the /64: openv6 detects it on its own.

Setting it up

1. Install

On the VPS (Ubuntu or Debian), run:

curl -fsSL https://raw.githubusercontent.com/thephux/openv6-releases/main/install.sh | sudo bash

Open http://VPS-IP:8080. Because the dashboard is reachable from the internet, a fresh install asks for the setup code that the installer prints before you can create the admin account. For anything beyond a quick test, put the dashboard behind HTTPS (built-in -tls-cert/-tls-key, or a reverse proxy such as Caddy).

2. Open the ports

Allow your proxy port range, for example 10001-11000/tcp, both in the server firewall and in the provider's cloud firewall or security group if it has one.

3a. With a /64

Nothing to configure. The auto pool follows the card's /64. Create proxies, set the scope to Internet (a password is then required) and export.

3b. With a routed /56 or /48

Enable the prefix in your provider's panel if needed, then in openv6 open the node and add a pool: the CIDR, for example 2001:db8:1200::/48, and the mode anyip. When creating proxies, choose that pool and tick "Each proxy in its own /64". Every account now sits in a different /64, which is as separate as IPv6 gets without more servers.

Only use anyip for prefixes that are really routed to the server. If the provider only gives an on-link /64, keep the auto pool.

Several servers, one dashboard

openv6 separates the dashboard from the nodes that run proxies. Add a node (Nodes → Add node), run the command it shows on the new machine, and it appears online within seconds. Nodes always connect out to the dashboard, so they work behind NAT.

A practical layout:

  • Dashboard and datacenter proxies on one VPS.
  • Home mini PCs as extra nodes for residential addresses.
  • The same VPS as a relay so home proxies are reachable from anywhere.

Keep them healthy

openv6 checks every proxy on a schedule (by default every 10 minutes), records latency, country and ISP, and can alert you on Telegram when a proxy fails twice in a row and again when it recovers. If the server reboots or an address disappears, the node adds it back automatically.

What it costs

A small VPS with IPv6 typically costs a few dollars a month, and the IPv6 space is included. openv6 Free runs 3 proxies on 1 machine; Pro is a one-time payment for unlimited proxies and machines. Compare that with renting per IP: self-hosted vs rented proxies.
