An anti-detect browser keeps every profile's fingerprint, cookies and storage separate. The proxy keeps the network separate. Get the proxy part wrong and the best fingerprint in the world won't help, because the platform simply sees twenty accounts on one IP.

This guide covers the formats, the protocol choice and a short checklist. The examples use proxies created by openv6, but the rules apply to any provider.

The formats each browser expects

Most anti-detect browsers accept a list of proxies, one per line, for bulk import. The format differs per browser. openv6's Export has a preset for each:

For other tools (MoreLogin, Incogniton, Kameleo, plain Chrome extensions, scripts) the generic formats work: host:port:user:pass, user:pass@host:port, a full URL such as http://user:pass@host:port, CSV or JSON.

Anti-detect browsers change their import screens from time to time; if a field name differs from what you see here, the format line above is what matters.

HTTP or SOCKS5?

Every openv6 port accepts both; the proxy detects the protocol from the first byte. So the question is only what the browser prefers:

  • SOCKS5 with remote DNS (socks5h, or a "remote DNS" toggle) resolves domain names at the proxy. Good default: the website's DNS lookups don't come from your own network.
  • HTTP works everywhere, including tools that only know HTTP proxies. With HTTPS sites the browser uses CONNECT, so the traffic stays encrypted end to end.

The checklist that keeps profiles separate

  1. One profile, one proxy, forever. Write the account name in the proxy's note (openv6: Edit → Note) so you always know which proxy belongs to which profile.
  2. Static, not rotating. An account that logs in from a new IP every session looks hijacked. Use proxies that keep their IP.
  3. Keep IPv4 fallback off on account proxies. Fallback lets a proxy open IPv4-only sites, but all such traffic leaves from the machine's single IPv4, shared by every profile.
  4. Match location signals. Set each profile's time zone, language and geolocation to the proxy's country. openv6's check shows the country and ISP websites see for each proxy.
  5. Mind the /64. Proxies inside the same IPv6 /64 can be grouped like a household. Spread important accounts across several /64s: see /64, /56 and /48 explained.
  6. Check before you log in. Run a check on new proxies first; a green result means the website really sees the expected address.

Importing a list

  1. In openv6, filter proxies by tag (for example facebook), select them and click Export.
  2. Pick your browser's preset. If the browser runs on another computer, choose how it connects: the LAN address, the public IP of a VPS, or a relay.
  3. Copy the list or download the file, then use the browser's bulk proxy import.
  4. Assign one proxy to each profile and run the browser's own proxy check.

Troubleshooting

SymptomLikely cause
Proxy check fails in the browser, works in openv6Wrong protocol or format selected in the profile; or the browser's machine can't reach the proxy port (firewall, VPN without LAN access).
Some sites load, one site shows a 502 or never loadsThat site has no IPv6.
Proxies stop working after turning on a VPNOn the proxy machine, the VPN takes the default route. openv6 routes proxies around it; with an IPv6 kill switch, nothing can get through.
Auth prompt appears in the browserUsername and password not imported; re-export with credentials.
