An anti-detect browser makes each profile look like a different device. A proxy makes each profile come from a different IP. But the profile also tells websites where it thinks it is: its time zone, its language, sometimes its GPS position. When those disagree with the IP, the profile tells two different stories, and that is easy to spot.

A typical example: an IP in Vietnam, a browser clock on America/New_York, and en-US as the only language. Any site can read all three with a few lines of JavaScript.

What to match

SettingWhat websites readMatch it to
Time zoneIntl.DateTimeFormat().resolvedOptions().timeZone, the clock offsetThe IANA time zone of the proxy IP, e.g. Europe/Berlin
Languagenavigator.languages and the Accept-Language headerThe usual language of the IP's country, e.g. de-DE
GeolocationThe Geolocation API (only after the user allows it)The latitude and longitude of the IP's city
WebRTCLocal and public addresses exposed by WebRTCThe proxy IP, or disabled. Never your real IP.

Other locale details (date format, number format, fonts) follow the language in most anti-detect browsers. Screen size, GPU and similar fingerprint values are about the device, not the location, so they don't need to match the proxy.

Get the right values

The values must come from the IP the website will see, so look it up through the proxy. A lookup from your own connection gives your own location.

By hand:

curl -x socks5h://user:pass@host:port https://ipinfo.io/json

The answer has timezone, country, city and loc (latitude, longitude). The language you pick from the country.

In openv6, every proxy check does this lookup through the proxy. Open the proxy and the Profile settings to match this IP section shows the time zone, the suggested language and the location, each with a copy button. Before the first check it tells you to run one.

Doing it for many profiles

Copying three values into fifty profiles is tedious and error-prone. Two ways around it:

  1. Let the browser fill them from the IP. Most anti-detect browsers have an "auto from IP" or "based on proxy" option for time zone, language and geolocation. It works when the browser can reach its own IP-lookup service through the proxy. Check one profile after the first launch: if the lookup failed, some browsers silently fall back to your real location.
  2. Import the values with the proxies. openv6's CSV and JSON export include country, timezone, language, city, latitude and longitude next to each proxy. Use them in a spreadsheet, a script, or your browser's API to set each profile.

If the browser's own IP lookup keeps failing with IPv6 proxies, its lookup service is probably IPv4-only. See why some sites fail over IPv6 proxies for a fix that doesn't expose your IPv4.

Picking the language

Use the country's most common browser language as the first entry, for example:

CountryLanguageCountryLanguage
United Statesen-USVietnamvi-VN
United Kingdomen-GBJapanja-JP
Germanyde-DEBrazilpt-BR
Francefr-FRIndonesiaid-ID

Adding English as a second language (vi-VN, en-US) is normal and common. What stands out is a language list that has nothing to do with the IP's country at all.

Checklist

  1. One profile, one fixed proxy (why).
  2. Check the proxy, then set time zone, language and geolocation from that check.
  3. Set WebRTC to use the proxy IP, or disable it.
  4. Open an IP-check page inside the profile once and confirm everything shows the same country.
  5. If you ever replace the proxy, run the check again and update the profile: a new address can be in another city.
